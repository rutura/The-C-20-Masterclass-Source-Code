Toolchain facts for later chapters (and for anyone teaching this live):
- Modules through CMake need `cmake_minimum_required(VERSION 3.28)`, `target_sources(t PRIVATE FILE_SET CXX_MODULES FILES x.cppm)` and Ninja. `.cppm` works on all three. Implementation units are ordinary sources on the `add_executable` line.
- Private module fragment (`module :private;`): MSVC and Clang OK, GCC 16 rejects it ("module already declared"). Header units are fragile (MSVC `import <print>` fails to link, GCC needs a failing manual pre-build, CMake has no support): paragraph only, no lecture.
- `import std;` through CMake: MSVC with `set(CMAKE_EXPERIMENTAL_CXX_IMPORT_STD "0e5b6991-d74f-4b3d-a41c-cf096e0b2508")` before `project()` (only `if(CMAKE_HOST_WIN32)`) and `CXX_MODULE_STD ON`; GCC and Clang by adding the library's module source (`std.cc` / libc++ `std.cppm`) to the target's module file set with `BASE_DIRS`; Clang needs libc++ (`-stdlib=libc++ -Wno-reserved-module-identifier`, also at link). Packaged as `import-std.cmake` with `target_use_import_std(target)` (copies in 17.6, 17.9 and 17.10). By-hand scripts: `17.6ImportStd/build-gcc.sh` and `build-clang.sh`. CMake prints an "experimental" dev warning; `-Wno-dev` silences it. MinGW cannot do `import std`.
- After `import std;`: no macros (INT_MAX, assert), no `printf` (use `import std.compat;`), unqualified `size_t` rejected by GCC and Clang. Each module unit must include what it names (reachable is not visible; MSVC is lenient). Interface partitions must not import internal partitions (Clang warns).
- Rebuild facts, identical on the three: editing `main.cpp` rebuilds main only; a body in a module interface rebuilds that module plus importers; the lowest module of a chain rebuilds all above it; `touch` rebuilds with no content check; a body in an implementation unit rebuilds that file only. Modules give no smarter incremental builds than headers; the gain is parse cost.
- Timings (ms, median of 3, unoptimized; headers / modules with `#include` / `import std`): clean build is 2 to 3 times SLOWER with modules plus `#include` (serial partition chain, std headers re-parsed), and `import std` pays a one-time std module build (3 to 4 s on MSVC), after which most rebuilds are fastest (exception: GCC touching the lowest interface, 1640 vs 1322). The full tables are in the 17.9 section of `NOTES.md`.
- Reuse for chapter 19: the `render` module (11.12 shape renderer as modules, `17.9ProjectModularize/modules`) exposes `Canvas`, `Color`, `Shape`; chapter 19's Mandelbrot can still use the 10.12 `Canvas` header version as planned.
