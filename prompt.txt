* The tools you have access to: 
    * Windows: GCC and Clang in: C:\mingw64\bin
        GCC 14.2 and Clang 19.1 in C:\mingw64\bin cannot link std::print/println
        (undefined std::__open_terminal), so they cannot verify lectures that use
        <print>. Do not use them to check those lectures. If you have to use them, 
        for example where you investigate ABI issues, just revert back to std::cout.
    * Visual Studio ide and msvc:
        MSVC (cl.exe 19.51, VS 2026 Community) is the reference compiler for this
        branch. It is not on PATH by default. Shell state does not persist between
        tool calls, so load the dev shell in the SAME PowerShell invocation as the
        build command:

            $vs = & "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vswhere.exe" -latest -prerelease -property installationPath
            & "$vs\Common7\Tools\Launch-VsDevShell.ps1" -Arch amd64 -HostArch amd64 -SkipAutomaticLocation

        Then build a lecture folder with CMake (3.30.2, no VS 2026 generator, so
        pass -G Ninja explicitly) and use an out-of-tree build dir so the lecture
        folder stays clean:

            cmake -S <lecture-folder> -B <build-dir> -G Ninja
            cmake --build <build-dir>
            & <build-dir>\rooster.exe

        Or compile a single file directly. Use /std:c++latest (or
        /std:c++23preview). Do NOT use /std:c++23: cl ignores it and <print> breaks.

            cl.exe /nologo /std:c++latest /EHsc /W4 main.cpp
